# Internal-tracking-label guard allowlist
#
# Consumed by bin/check-internal-labels.py.  Each non-comment line is:
#
#     <repo-relative-path><TAB><exact-substring><TAB><reason>
#
# A label-regex hit is suppressed ONLY when the offending file's path
# equals the entry path AND the offending line contains the exact
# substring.  Keying is (path, substring) -- never line number, because
# line numbers drift under any edit above them.
#
# Content is more stable than a line number, but it is NOT stable, and
# adopting the formatter proved it twice in one commit.  A substring is
# only as durable as the two things it spans:
#
#   * Quote style is not content.  `, 'name': 'Item ` stopped matching
#     when the formatter normalized the fixture to double quotes.  Write
#     an entry in the style the formatter produces -- double quotes --
#     since that is the only style that survives it.
#   * A substring must appear on the line it suppresses.  The
#     `llama3-2-11b` entry covered a `llama3-2-90b` hit for as long as
#     the two shared a line, which its own reason column recorded as
#     though it were a rule; the formatter split the list and the
#     suppression stopped covering anything.  One entry per hit, and
#     never an entry that works by proximity.
#
# Both failures are the shape this guard exists to catch, arriving in the
# guard's own configuration: a suppression that silently stops covering
# its target reads exactly like a clean scan.
#
# Every entry below is a genuine fixture record value or markdown
# list-item test fixture -- NOT a planning/tracker reference.  Adding a
# new entry is intentional friction: it produces a reviewer-visible diff
# here and must state why the hit is data, not a leak.  Do NOT add an
# entry to silence a real tracker label -- reword the source instead.
#
# Columns are TAB-separated.
